# Reqable + Chrome DevTools MCP (Windows)

This is a **local AI troubleshooting workflow** for the Windows Reqable desktop app. It does not replace, deploy, or remotely start the Reqable Bridge service.

## Goal

Connect an MCP-capable AI coding assistant to two upstream, maintained tools:

- **Reqable MCP**: inspect live capture records, query an ID or URL, create an HTTP API test, and manage debugging rules.
- **Chrome DevTools MCP**: navigate a test page, inspect its console/network requests, and verify browser behavior.

The configuration lives at the repository root in `.mcp.json` (portable `mcpServers` format for modern VS Code Copilot). It is **not** a `.vscode/mcp.json` file, which uses a different `servers` schema.

## Windows setup

1. Install and launch the **Reqable desktop app** (prefer v3.3.11 or newer), Google Chrome, current Node.js LTS (includes `npm`/`npx`), and an MCP-capable VS Code AI extension or Copilot harness.
2. In Reqable, open **Tools / 工具 → MCP Server / MCP服务器**. Follow the configuration guide generated by your installed version, **including the required local access token** introduced in Reqable v3.3.9. Reqable's own generated setup is authoritative if it differs from this template.
3. Open this repository as a **local Windows workspace** in VS Code. In **Chat: Open Customizations → MCP Servers**, confirm that `reqable` and `chrome-devtools` are discovered; start/enable them for the intended agent harness. If workspace-root `.mcp.json` discovery is unavailable, add each stdio server using **MCP: Add Server** and the documented commands below in your personal configuration.
4. For Reqable's package-based stdio entry, the upstream example is `npx -y reqable-mcp-server`. For Chrome, it is `npx -y chrome-devtools-mcp@latest`. Do not paste any real MCP access token into `.mcp.json`, source control, chat transcripts, or shared screenshots.
5. Enable Reqable capture and its normal system proxy only when ready for a test. Chrome DevTools MCP may launch a separate Chrome instance; verify that its requests actually pass through the intended Reqable proxy. Install/trust the local Reqable CA only when needed and according to Reqable's desktop instructions.

> **Access-token caution:** An MCP stdio process may start successfully even when its API calls fail authentication. Check an actual read-only tool invocation. If your Reqable version requires an extra token argument, environment setting or app-generated command, use Reqable's in-app setup instead of inventing a flag.

## Read-only smoke tests

Ask the agent in VS Code:

> Use the Reqable MCP tools to find the current live capture status and list/filter requests for `reqable.com`. Report the tool name and results. Do not create, replay, rewrite, or delete traffic.

Then ask:

> Using Chrome DevTools MCP, open `https://reqable.com/zh-CN`, inspect its page title and list one network request. Report the tool outputs. Do not submit forms.

Next, confirm the request is visible in Reqable and compare its URL, method and response status. The two MCP servers are independent: seeing a request in Chrome does not prove it crossed Reqable.

## What to ask the AI to do next

- Explain one captured request ID (URL, method, headers, response status, timing).
- Group requests by domain/path and identify a public API endpoint.
- Create a Reqable API test from **an approved, read-only sample request** and inspect response parsing.
- Propose a locally scoped, reversible rewrite rule for an owned test page; apply only after review.

Keep `--scope` at its upstream default (`minimal`) initially; `--scope all` registers many additional tools and is not needed for this smoke test.

## Relationship to Reqable Bridge

`Reqable Bridge` is the separate Windows-to-Android forwarding/control project. Its original README currently describes a hotspot receiver and near-real-time HAR forwarding. This MCP configuration **does not** deploy to Alibaba Cloud, turn a sleeping Windows computer on, provide remote control from ChatGPT mobile, or automatically add HAR exports/pause buttons to the cloud dashboard. Those are separate bridge features requiring their own implementation and validation.

Keep MCP local to the trusted Windows machine. Do not expose an unauthenticated Reqable API, MCP endpoint, Chrome debugging port, or capture records to the public internet. Maintain data redaction for cookies, credentials and authorization headers.
